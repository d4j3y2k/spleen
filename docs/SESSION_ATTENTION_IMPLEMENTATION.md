# Session attention and optional assessment

Updated 8 November 2026. Task assessment is off by default and is separate from live working/unread indicators and the dormant [next-chat ranking experiment](DECISIONS_TRIAL.md). See [live indicator coverage](LIVE_INDICATORS.md) for those local sources and the [independent readiness review](PUBLIC_READINESS_2026-11-08.md) for the latest verification and remaining limits.

The native app now retains bounded chronological user/assistant message windows alongside its old recognition excerpts. These carry provider/host identity, source update version, message IDs/order, and explicit truncation/incomplete flags. Commentary and tools do not become final replies. The latest unanswered user input is locally ongoing; inferred completion never stands in for runtime or unread state.

## Implemented

- Background enrichment reserves four of eight reads for newest catalog entries independently of the five-card/eight-candidate ranking shortlist. Old caches backfill message windows; ordinary saved destinations, labels, pins and context preferences retain their existing storage contract.
- Decisions task assessment has four outcomes: ongoing, waiting for user, appears finished, unclear. Each request contains one bounded recent conversation, at most 20,000 encoded bytes. A stored message longer than 2,400 characters keeps its first 800 and its ending, with a marker where the middle was omitted; it is sent flagged as truncated and the window still counts as complete. If the full message contains recognizable secret-like text, only its beginning is kept and the window stays incomplete, because a cut could otherwise split a credential past the screening. Windows cached by earlier versions with only a beginning are read again. Any compaction to fit the byte limit explicitly marks incomplete evidence and prevents a finished classification. The response validator checks question, options, normalized finite probabilities, confidence shape and a unique winner. This validates protocol correctness, not classifier quality. An appears-finished choice also needs at least 70% probability; weaker ones stay unclear and are not demoted. The 70% is a starting guess, not calibrated on labeled sessions.
- Exact content/prompt versions avoid repeated classification on metadata-only changes. Full source-version equality rejects late results; new input immediately invalidates earlier completion. The app processes one request at a time over at most 16 recent available windows. The command-line trial has a 20-attempt per-launch ceiling plus its durable manifest allowance; assessment on open has its separate daily cap below. Manual reviews authorize one request each.
- Ongoing/waiting tasks get priority; appears-finished tasks get a soft demotion. Hard suppression is implemented but **disabled** pending classifier evaluation. Even when validated, suppression requires fresh, known read + idle state newer than the assessed messages, and cannot remove pins. Suppressed rows remain searchable.
- Separate live-state samples include exact identity, local host, source, sequence, observation and expiry. Unknown fields stay nil. Older, future, wrong-host and stale samples are rejected. Read/unread, working and approval/input are independent of prose. Blue dot, working spinner (static under Reduce Motion), and amber blocker badges render on fixed cards with accessibility labels. Expired samples disappear; navigation does not manufacture acknowledgement.
- A visible compass keeps its identities, ordering and selected item while badges/assessments update. Reordering applies on the next invocation.
- Fixed the dormant remote pin-before-center bug and excluded the local current conversation from the app's model shortlist. Fixed saved generic labels masking fresh observed topics, expired context resurrection through a 30-day fallback, and cached ranking overlooking individual 30-minute working-set expiries. Boundary snapshots are prepared in the background and selected by binary search during opening.

## Current integration boundaries

Codex uses guarded Desktop unread-marker polling and optional trusted lifecycle callbacks. Working callbacks have a 15-second freshness limit and do not supply a continuous runtime subscription; the positive unread→viewed UI transition still needs verification. The isolated app-server's runtime state is not used for badges. Claude's optional observers read route, title, visit, available reply-age and current Code work-control metadata; message text is not read. See [Live indicators](LIVE_INDICATORS.md) for source coverage, installation and remaining limits.

Assessment requests contain only chronological message roles and text, truncation/coverage flags, and fixed classifier instructions. Thread IDs, message IDs, project paths, titles and timestamps are not added as separate request fields. They can still occur inside the message text: these excerpts are **not anonymized**. Automatic secret screening is an additional conservative check, not a guarantee that private information cannot be transmitted. Manual review shows the exact payload so the user can make that decision.

## Finite Decisions review and activation

Normal launch makes zero paid requests, including when a standing opt-in is restored. The [official Decisions guide](https://developers.openai.com/api/docs/guides/decisions) was checked for `gpt-6-luna`, `input_json` and the choice schema.

`Spleen --data-dir /absolute/state --export-attention-trial /absolute/review` reads at most eight recent scoped sessions through the existing read-only client, exports at most two complete answered windows, and writes exact request JSON plus `trial.json`. This is local-only; requests contain conversation text and must be reviewed before transmission. The manifest allows only those exact request hashes, at most two requests, and expires after 24 hours. The review files use private directory/file permissions.

After reviewing the exported bytes and choosing a credential file, launch with `--attention-trial /absolute/review/trial.json --attention-credential-file /absolute/key-file`. The app never searches for a credential. A changed conversation produces a different payload and is rejected by the exact-payload transport. The durable ledger prevents retries from exceeding the allowance. Model quality and false-exclusion rate on real labeled tasks remain unmeasured. Hard suppression stays disabled for this trial.

## Verification

Regression fixtures cover unanswered requests, incomplete and compacted text, provider/host/order identity, stale responses, unread final results, working/blocker protections, pins, search retention, clock/expiry boundaries and exact-payload admission. Native app checks exercise injected asynchronous classification and live samples, fixed card positions, next-opening ranking, and search. Native light/dark previews use explicitly synthetic badges; they are not evidence of a live Desktop feed.

The independent review passed 254 package tests and 421 native checks, including the restored-consent startup boundary. These are protocol and integration checks, not evidence of classifier accuracy. See the [verification record](PUBLIC_READINESS_2026-11-08.md).

## In-app reviewed assessment (November 7)

Settings → Decisions assessment → Review selected conversation snapshots the selected Codex window and shows the exact JSON before one explicitly approved request. A file chooser reads the chosen `.env.local` or raw-key file in memory; it does not save or print the key. Credential files must be regular, non-symlink, owner-only files. A saved assessment-on-open opt-in loads its transport at launch without starting a request.

The result goes through the same versioned parser, stale-window check, local assessment cache and next-opening ranking as the background adapter. Stop discards late results; errors are not retried. Visible compass positions remain fixed. Each manual request gets a one-request durable ledger and expires after 60 seconds. The background HTTP timeout for this path is five seconds, while opening/search never waits for it. The ranking adapter retains its separate 750 ms deadline.

Core prompt version v2 rejects missing user-request evidence, distinguishes unresolved work from an unanswered necessary user decision, and resolves old approval questions using later replies. Full transcripts, runtime activity and unread status are not inferred. No hard hiding is enabled.

An earlier API smoke test returned the expected labels for three fictional examples. That small check does not establish accuracy, calibration or representative latency. The independent readiness review used injected transports only and made no paid requests.

## Assessment on open (opt-in, November 7)

Settings → **Assess cards on open…** is a standing opt-in. After consent and a chosen key file, each press of the Spleen shortcut assesses only the local Codex cards in the compass at that moment whose message text changed since their last assessment. Cards you don't see are never sent; Claude remains metadata/status-only. Turning it on sends nothing by itself, and launch sends nothing.

- **What is sent:** the existing recent-message source (up to three turns/six messages, 20,000 bytes per request; long messages as beginning and ending), never screenshots or tool/reasoning output. Known credential-like text, incomplete/compacted windows, unanswered input, and sessions that are working or awaiting approval/input are skipped. So are sessions where Codex activity (a new message, model call or tool) is at least one second newer than the retained messages: those messages refresh only when a turn finishes, and working signals last just 15 seconds. Such cards show "Work ongoing" until the next turn's messages arrive. Secret screening is conservative, not guaranteed sanitization.
- **When:** the press records its Codex cards. Requests run one at a time, in the background; opening never waits. A press's cards are finished even if the panel closes, but nothing is sent more than 30 seconds after that press. Labels update on the open cards; order changes apply at the next opening.
- **Caching:** the version includes message identities/text and prompt version, not catalog timestamps. Cached assessments survive metadata refresh gaps and restarts; unchanged cards reuse their labels, and new messages invalidate them.
- **Cap:** at most 100 requests per local calendar day, enforced by a durable per-day ledger in `assessment-ledgers/` named by the assessment scope, so it survives restarts, continues across pause and re-enable, and resets at midnight. Ledgers older than yesterday are removed. When the cap is reached, nothing more is sent until the next day; affected text becomes eligible then. This is a request limit, not a guaranteed dollar cap. Manual reviews have separate one-request allowances.
- **Consent:** `assessment-on-open.json` stores the consent ID, scope, daily cap and key file path (owner-only), never the key. A consent given for the earlier 6,000-byte scope does not cover the longer excerpts: Settings says so, and nothing is sent until assessment is turned on again. Pause cancels pending work and persists the disabled state; turning it back on needs a new consent action.
- **Errors:** HTTP status codes are surfaced. A 401/403 or other rejected request pauses assessment and says so in Settings, since it would fail identically every time. A 408/429/5xx reply or a network failure keeps that text eligible for a later opening after a minute. The daily ledger accepts the same payload at most three times a day, and every attempt counts toward the cap. A deliberately reviewed manual request has its own one-request ledger. A key file or settings file that cannot be read at launch shows a paused status instead of silently reporting Off. Each failed attempt still consumes its reservation; nothing is retried within a press.

No permissions, approvals, or external agent actions are inferred from model output.
